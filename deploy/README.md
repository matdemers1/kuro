# Deploying Kurō

Two images, both published by CI on every green push to `main`:
`ghcr.io/matdemers1/kuro-server:sha-<40 hex>` (API, jobs, the built web app) and
`ghcr.io/matdemers1/kuro-cr:sha-<40 hex>` (the Crunchyroll sidecar). Kurō runs on the Zima at
**https://kuro.dormice.ai** and is deployed by **Shipyard**, never by SSH.

| File | On the Zima | What it is |
|---|---|---|
| `zima/compose.yml` | `/DATA/kuro/compose.yml` | Postgres 16, the sidecar, the server. No host ports. |
| `zima/compose.tunnel.yml` | `/DATA/kuro/compose.tunnel.yml` | cloudflared: tunnel `kuro` → `http://kuro-server:3300`. |
| `server.env.example` | `/DATA/kuro/server.env` | Generated by `zima-onboard.sh`. |
| `shipyard.kuro.yml` | `/DATA/shipyard/apps/kuro.yml` | The Shipyard manifest; the host copy counts. |
| `d3auth-client.json` | D3 Auth console › Apps › Import | The `kuro` client for Sign in with D3 Auth (GL-001). |
| `zima-onboard.sh` | run once on the host | Writes `/DATA/kuro` with generated secrets; never prints them. |

## What the image promises

- `GET /healthz` — 200 while the process is up (Docker HEALTHCHECK).
- `GET /health` — `{ ok, version, schemaRevision, database, sidecar }`; 503 if the database or sidecar is down. The manifest's check.
- Boot: pending migrations run only after `/data/backups/<stamp>-pre-migration.dump` is written.
- `node dist/cli/backup.js` / `node dist/cli/restore.js --file … --yes`.
- Labels: `dev.d3cloud.shipyard.schema`, `dev.d3cloud.shipyard.migration` (from a `Shipyard-Migration:` trailer), `dev.d3cloud.shipyard.env`.

## First deploy

1. Tunnel `kuro` and the proxied CNAME `kuro.dormice.ai` (remotely managed; created through the Cloudflare API).
2. Copy `deploy/` and the tunnel's `tunnel.env` to the Zima; `sh zima-onboard.sh ./tunnel.env <sha>`.
3. Mount `/DATA/kuro` and the `kuro_backups` volume into the Shipyard agent (keep `docker-compose.yml.bak-pre-kuro`), then dry-run.
4. Open https://kuro.dormice.ai, run setup with the token from `server.env`.
5. D3 Auth: import `d3auth-client.json`, put `D3AUTH_*` in `server.env`, redeploy.

## Every deploy after that

```bash
docker compose -p shipyard run --rm --no-deps --entrypoint shipyard-run agent deploy kuro <40 hex>
```

from `/DATA/shipyard` until a Shipyard token names `kuro`; then `shipyard_deploy app=kuro`.
Report each image's SHA and the `schemaRevision` after every deploy.
